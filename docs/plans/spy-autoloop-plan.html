01 · Outcome

Spy Loop cần tạo ra gì?

Với mỗi topic, hệ thống chạy một lượt có giới hạn thu thập: tìm bằng yt-dlp, lấy transcript/thumbnail, thu gợi ý trực tiếp quanh video corpus đã duyệt, rồi để Gemini Flash phân tích. Kết quả luôn vào hàng duyệt; P0 không tự quyết định thay user.

Đầu vào

Topic, keyword do user cung cấp và corpus/import batch đã được xác nhận.

Đầu ra P0

Observation có provenance, asset/transcript, Gemini analysis có evidence và Inbox để user quyết.

Người quyết

User duyệt nạp corpus, promotion và shortlist/reject. Agent chỉ thu thập/diễn giải evidence; P0 không auto-triage semantic.

Ranh giới chính: Auto-Loop sở hữu corpus membership, recommendation review state và report. Nguồn thô là yt-dlp/C3; Gemini Flash chỉ tạo phân tích có dẫn chứng trên những input đó. Không có nhánh nào được dựng global candidate index.

03 · Architecture

Thành phần và dữ liệu

Configuration

  • config/topics/*.json: topic, language, keyword, collection bounds.
  • config/spy-loop.json: schedule, retry/timeout và Telegram.
  • Data API key, nếu còn, là capability tùy chọn ngoài P0; không phải điều kiện chạy loop này.

Source runtime

  • YtDlpAcquisitionPort: search, inspect, channel list, transcript, thumbnail.
  • RecommendationCapturePort: C3 capture trực tiếp quanh seed corpus; browser/yt-dlp adapter chỉ khi thực sự cung cấp evidence đó.
  • LoopRunner: checkpoint, resume, report và collection bounds.

Analysis runtime

  • GeminiFlashAnalysisPort: multimodal analysis độc lập với raw collector và LlmPort text-only hiện có.
  • Input manifest: metadata observation, transcript chunks, thumbnail/frame artifact refs và chỉ analysis context đã được duyệt; không có cookie, session hay private topic metadata.
  • Analysis-run record: kind, immutable input refs/digests, model/prompt-policy, attempt/status/expiry. Expiry lấy theo evidence hết hạn sớm nhất; không ghi unavailable giả vào schema interpreted.

Persistence & surface

  • topics, corpus membership, candidates và topic sources.
  • Import/recommendation batch + item + immutable provenance links; asset/evidence artifact 30 ngày.
  • Dashboard: capture preview, selective confirm, Inbox/report. Writer Spy MCP vẫn read-only.

Provenance phải lưu được

Mỗi observation/candidate phải mang một nhãn đóng. P0 dự kiến dùng ytdlp_search, corpus_import, corpus_suggestion, seed_config hoặc manual_user. Hai nhãn corpus chỉ hợp lệ khi có batch/item audit và immutable link về seed/import; manual_user chỉ là lời khai của user, không phải bằng chứng lịch sử. Không system path nào được phép ghi nó.

05 · Current P0

Feature làm trước: Corpus Intelligence Loop

P0 mới là một vertical slice hoàn chỉnh từ corpus được user xác nhận đến Inbox: yt-dlp lấy raw observation → C3 thu gợi ý trực tiếp quanh seed → yt-dlp lấy transcript/thumbnail → C2 Gemini Flash phân tích → user review. Đây mới là đường mà user sẽ vận hành; Data API/quota accounting không được chặn nó.

Agy A · yt-dlp source plane

Map và invert acquisition/search so P0 calls yt-dlp first. Define normalized raw observation, capture bounds, capability/failure states and a fake that proves Data API is never touched.

Agy B · C3 corpus/recommendation plane

Implement batch/item/provenance contract for browser corpus import and direct recommendations. Enforce confirmed seed, depth 1, per-seed ceiling, draft isolation and selective confirmation.

Agy C · C2 Gemini analysis plane

Define multimodal Gemini Flash port, structured schema, input manifest, prompt/injection boundary, artifact/evidence retention and review-only semantics.

Agy D · adversarial release gate

Write independent fixtures for NoDataApi, bounded yt-dlp/C3 capture, draft/confirm provenance, restart/idempotency, unavailable states and evidence-bearing Gemini output.

Trình tự bàn giao

  1. Codex chốt interface, storage boundary và hard-gate acceptance trước khi có code.
  2. Agy A chuyển source plane sang yt-dlp; Agy B làm import/corpus membership trước vì C3 chỉ được chạy trên seed đã confirm.
  3. Agy B thêm C3 capture; Agy A làm enrich sau khi user confirm selected item. Agy D viết fixture độc lập song hành.
  4. Agy C nối Gemini Flash review-only vào artifact manifest; Codex chạy gate và chỉ ghi repair note theo file:line.
Không suy diễn nguồn: C3 capture chỉ ghi observation. Chỉ item user chọn confirm mới được promote; target thiếu channel identity vẫn là needs_identity, không được tự tạo candidate channel từ handle/text.

05 · Non-negotiable

Ràng buộc không được phá

C1 · Tự chủ dữ liệu

Không vidIQ hay provider intelligence ngoài. P0 lấy raw YouTube observation bằng yt-dlp và C3 capture có provenance; Data API chỉ là capability deferred, không phải fallback ngầm.

C2 · Toàn bộ semantic analysis qua local agy

Local agy gọi Gemini Flash cho transcript, thumbnail/frame và raw metadata đã được thu nhận. Kết quả lưu model, prompt policy, input/evidence và thời điểm; review-only cho đến khi user duyệt policy auto-action riêng.

C3 · Corpus import + gợi ý liền kề

Browser-assisted capture là workflow quan trọng sau khi user xác nhận corpus. Gợi ý chỉ xuất phát từ seed confirmed, depth 1, host/identity được server xác thực, batch/owner/evidence đầy đủ; không crawler đệ quy, không lưu cookie/session capture và không rửa nguồn.

  • Raw public observation/artifact và mọi derivative recomputable chỉ giữ trong cửa sổ trượt 30 ngày; purge artifact vẫn giữ audit digest/tombstone.
  • Nếu report theo ngày vẫn dùng Pacific, mọi report/resume key phải đi qua một reportDay()/quotaDay() duy nhất; không cắt ngày UTC.
  • Metric thiếu mẫu phải trả unavailable/insufficient_sample, không nội suy số.
  • Parser deterministically extracts IDs/URL/time; Gemini may analyze meaning but cannot turn an unobserved fact into a measurement. keyword_candidates must say it is Gemini-derived unless it is a raw platform tag.
  • Gemini Flash is inference over bounded assets, not a market-data provider. Prompt content from titles/transcripts is untrusted data, not instruction.

06 · Release gate

Checklist nghiệm thu P0

  • A1 · NoDataApi: production P0 fixture injects a throwing Data API port and successfully executes yt-dlp search, enrichment, C3 and analysis without touching it.
  • A2 · Bounded acquisition: yt-dlp search has a literal query/result ceiling; C3 only accepts a confirmed seed, depth exactly 1 and ≤20 suggestions/seed. Timeout/retry/cancel are stored as unavailable/failed observations, never hidden.
  • A3 · Raw evidence: each yt-dlp/C3 observation records canonical URL/identity, capture time, method/adapter version and server-generated artifact digest. Raw title/channel/tag/position stay separate from derived analysis.
  • A4 · Corpus and C3 isolation: draft import/recommendation batches create no candidate/topic row; selective user confirm runs atomically. Two seeds may retain two observations for one target, but promotion dedupes the target while preserving both links.
  • A5 · C2 evidence contract: every Gemini result validates against a JSON schema and stores model/version, prompt-policy, input-manifest digest, cited transcript/asset refs, observation time and status in an analysis-run record. A malformed/failed response publishes unavailable, not a guessed result or a fake interpreted profile.
  • A6 · Truth and safety: output never presents Gemini keyword candidates as search volume/rank/CTR/global trend; titles/transcripts are untrusted data and cannot change the prompt policy. Semantic output cannot auto-reject or mutate corpus state in P0.
  • A7 · Restart, retention and access: crash/retry yields no duplicate batch/item/report; raw public artifacts purge after 30 days with audit tombstone; Writer Spy MCP remains unable to call loop mutation tools.
  • T1 · if daily scheduling/report keys remain, Pacific date tests cover restart crossover, digest 08:00 VN and both sides of midnight without UTC string slicing.
  • Provenance · stored source values belong to the closed allowed union; no system path writes manual_user. A repo gate cannot prove a human did not paste provider-derived data, so environment-level tool audit remains a separate control.

P0 passes when deterministic source/provenance/C2 gates are green without a Data API key. A future Data API capability requires its own quota gate; it cannot silently broaden this P0.

07 · Next after P0

Lộ trình intelligence

M1 · Change intelligence

So sánh repeated yt-dlp observations trên đúng managed corpus: upload, cadence, views/day, freshness. Không dựng discovery hay review-state thứ hai.

M5a · Recommendation co-occurrence

Similar signal chỉ trong stored C3 observation: seed video, position quan sát, thời gian và count hỗ trợ. Không gọi đó là global similarity.

M2 · VPH quan sát

Lấy ≥2 raw view-count observations bằng yt-dlp trong cửa sổ 30 ngày; chỉ hiển thị VPH khi timestamps và raw points hợp lệ. Data API polling là phương án optional sau này, không phải P0.

M3/M4/M5b

Opportunity card evidence-first, OAuth Analytics cho owned channel và corpus-bounded embeddings/analysis trên evidence đã chốt.

Nguồn chi tiết: workflow visual, workflow diễn giải tiếng Việt, active P0 hard gate, deferred Data API quota gate, và intelligence roadmap.
