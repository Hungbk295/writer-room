Spy Keyword Run API + Board

2026-09-27 · DRAFT · Đứng trên v3-lean đã triển khai + 16 endpoint /api/spy/dash/* đã có (spy-dashboard-api.html)

0 · Kết luận

Nhu cầu: chạy nhiều keyword trong ngách theo yêu cầu, rồi xem kết quả trên board để rút ra key còn khoẻ và video outlier. Hiện trạng: phần đọc đã có gần đủ (16 endpoint dash), phần ghi/chạy theo lô thì chưa có — weekly chỉ search ≤ weekly_keyword_budget (12) keyword active xoay theo last_checked_at, không có cách bảo "chạy ngay 40 keyword này". Web chưa có màn nào đọc /api/spy/dash.

Quyết định đề xuất:

  • Thêm 3 endpoint write: bulk-add keyword, bulk-decide, và POST /api/spy/keywords/run — chạy một tập keyword ngay, nền, ghi vào bảng run riêng (keyword_runs), tái dùng nguyên khối W1+W3 của weekly.
  • Không đụng loop_ticks: nó có UNIQUE(topic_id, quota_day, mode) + CHECK(mode IN setup|daily|weekly) — một run/keyword/ngày là không đủ, phải bảng riêng.
  • Mở rộng /dash/keywords với outliers_7d/28d + videos_found + group_key — đây chính là cột "key nào sinh outlier".
  • Board UI: 1 tab mới trong trang Spy Loop hiện có (SpyLoop.tsx), 3 panel: Keyword health (group theo ngách, bulk action), Run launcher (estimate quota → chạy → progress), Outlier board (group theo keyword tìm ra nó).
  • "Ngách" ở phase này = group_key nhẹ trên topic_keywords (do người đặt). Bảng niches đầy đủ của v3.1 (audience/situation/problem/painpoints) là phạm vi riêng, spec vẫn DRAFT — không gộp vào đây (xem §6 quyết định mở).

Luật bất biến giữ nguyên (tôn chỉ 1): máy/run chỉ ghi topic_videos, video_daily_views, sức khoẻ keyword, và kênh candidate status='new'. Kênh/keyword active|paused vẫn chỉ qua decide với actor='human'. Bulk-add do người bấm nên được ghi decisions actor=human, không vi phạm.

2.1 · Bên trong một run — tái dùng W1/W3, không viết lại

for kw in keywords:
  if quota.remaining('search') <= 0: dừng, đánh dấu phần còn lại skipped_quota
  search.list(q=term, type=video, order=viewCount, maxResults, regionCode, relevanceLanguage, publishedAfter)
  videos.list(stats) cho toàn bộ hit
  → upsertTopicVideo(source='keyword_run', foundByKeyword=termKey) + recordVideoDailyView
  → updateKeywordCheck + INSERT keyword_checks (lịch sử)
  → outside hits → best-per-channel map (giống W1)
sau vòng keyword:
  nếu scanChannelsCap > 0: quét ≤cap kênh ngoài follow (playlistItems+videos.list ~2–3 unit/kênh)
    → baseline → outlier_score cho hit → upsertTopicChannelCandidate(status='new', discoveredVia='keyword_run', discoveredFrom=termKey)
    → video kênh đó → upsertTopicVideo + outlier_score

Cần tách block W1 (modes.ts:335–457) và W3-scan (modes.ts:459–570) thành hàm chia sẻ runKeywordSearches(ctx, keywords, opts) / scanOutsideChannels(ctx, hits, cap) — weekly gọi lại đúng hàm này, tránh hai bản code trôi nhau.

Chi phí: 1 keyword ≈ 1 search call + 1 videos.list unit; 40 keyword ≈ 40/100 search call ngày + ~40 unit. Multi-key rotation (youtubeDataApiKeys) đã có sẵn.

3 · Schema v14

CREATE TABLE keyword_runs (
  run_id TEXT PRIMARY KEY,
  topic_id TEXT NOT NULL REFERENCES topics(topic_id),
  params_json TEXT NOT NULL,           -- termKeys/group/filters đã resolve
  status TEXT NOT NULL DEFAULT 'running' CHECK(status IN ('running','done','failed','skipped_quota','cancelled')),
  n_keywords INTEGER NOT NULL,
  keywords_done INTEGER NOT NULL DEFAULT 0,
  search_calls_used INTEGER NOT NULL DEFAULT 0,
  general_units_used INTEGER NOT NULL DEFAULT 0,
  new_candidates INTEGER NOT NULL DEFAULT 0,
  started_at TEXT NOT NULL, finished_at TEXT, error TEXT
);
CREATE TABLE keyword_run_items (
  run_id TEXT NOT NULL REFERENCES keyword_runs(run_id),
  term_key TEXT NOT NULL,
  status TEXT NOT NULL,                -- done|failed|skipped_quota
  n_results INTEGER, n_followed INTEGER, median_views REAL,
  outliers_found INTEGER,              -- số video ≥ outlierMultiple sau khi quét baseline
  error TEXT,
  PRIMARY KEY (run_id, term_key)
);
CREATE TABLE keyword_checks (          -- trend "key còn khoẻ/cạn"
  topic_id TEXT NOT NULL, term_key TEXT NOT NULL, checked_at TEXT NOT NULL,
  n_results INTEGER, n_followed INTEGER, median_views REAL, run_id TEXT,
  PRIMARY KEY (topic_id, term_key, checked_at)
);
ALTER TABLE topic_keywords ADD group_key TEXT;      -- ngách nhẹ, do người đặt
CREATE INDEX idx_topic_videos_keyword ON topic_videos(topic_id, found_by_keyword);

loop_ticks không đụng vào (UNIQUE+CHECK). topic_videos.source thêm giá trị keyword_run — cột TEXT không CHECK nên chỉ là convention, ghi vào /dash/meta enums.

6 · Quyết định mở cần JC chốt

  1. Ngách nhẹ hay nặng: group_key text trên keyword (đề xuất — đủ cho "chạy nhiều keyword trong ngách" + group trên board) vs bảng niches đầy đủ của v3.1 (audience/situation/problem/title_pattern + gán video). v3.1 còn DRAFT → làm sau.
  2. Outlier ngoài follow: run có tự quét baseline kênh lạ (scanChannelsCap mặc định 10, ~2–3 unit/kênh) hay chỉ xếp view thô? Đề xuất: có, vì không quét thì scope=external của /dash/outliers gần như rỗng.
  3. Board ở đâu: tab trong SpyLoop (đề xuất, tái dùng TopicSwitcher/Inbox) hay route riêng /spy/board.

8 · Tiêu chí chấp nhận

  1. Bulk add 50 term → 50 dòng pending (origin=user, group đúng); 1 lần activate → 50 active + 50 dòng decisions actor=human.
  2. Run 20 keyword: mọi item có dòng keyword_run_items (n_results/median_views), search_calls_used ≤ số keyword, quota hết giữa chừng → phần còn lại skipped_quota, run vẫn done.
  3. Chạy lại cùng keyword ngày hôm sau → keyword_checks có 2 dòng → board hiển thị trend median_views.
  4. /dash/keywords trả outliers_28d khớp SELECT COUNT(*) FROM topic_videos WHERE found_by_keyword=? AND outlier_score≥threshold.
  5. hitl_violations = 0; không endpoint write nào dưới /dash.
  6. Weekly/daily/setup không đổi hành vi (test cũ xanh, keyword source mới không rơi vào baseline_eligible).
