1 · Định nghĩa

Khái niệmĐịnh nghĩa
NgáchMột tệp khán giả trong topic: ai (người xem là ai), hoàn cảnh (đang ở đâu), vấn đề (kẹt ở đâu) + nhóm keyword + mẫu title để gán video. Không phải chủ đề: "Investing" là chủ đề; "người 30–40 tuổi sợ mình tụt hậu tài chính" là ngách.
Ngách focusTối đa 2 ngách mỗi topic tại một thời điểm (sửa 2026-09-25, ban đầu chốt 1), do người chọn. Weekly chia đều search cho các ngách focus; painpoint được đào sâu ở từng ngách.
PainpointCâu hỏi ngầm / vấn đề của viewer rút từ comment: hoàn cảnh, rào cản, mong muốn, kèm lời nguyên văn và số bằng chứng. Gom theo hoàn cảnh + rào cản, không theo chủ đề (v2 đo: 2,64x so với 1,78x).
Chưa gánKeyword/kênh không khớp ngách nào. Khi ~5 keyword chưa gán tụ lại thành cụm → tín hiệu ngách mới ở Niche review.

9 · Database — thay đổi so với v13

Tổng bảng mới từ v3 + v3.1: 5 (topic_videos, video_daily_views, decisions, niches, painpoints) — so với 16 của v2. Tái dùng video_comments có sẵn.

CREATE TABLE niches (
  niche_id TEXT PRIMARY KEY,
  topic_id TEXT NOT NULL REFERENCES topics(topic_id),
  name TEXT NOT NULL,
  audience TEXT NOT NULL,          -- ai
  situation TEXT NOT NULL,         -- hoàn cảnh
  problem TEXT NOT NULL,           -- vấn đề
  title_pattern TEXT NOT NULL,     -- regex gán video vào ngách
  status TEXT NOT NULL DEFAULT 'proposed'
    CHECK(status IN ('proposed','focus','queued','done','rejected')),
  n_videos INTEGER, n_channels INTEGER,
  median_rel_views REAL,           -- median(view / baseline kênh)
  outlier_rate REAL,               -- % video ≥ outlier_multiple
  comments_per_1k_views REAL,
  opportunity_score REAL, score_reasons_json TEXT,
  computed_at TEXT,
  created_by TEXT NOT NULL CHECK(created_by IN ('agent','human')),
  created_at TEXT NOT NULL, decided_at TEXT
);
-- Đúng 1–2 ngách focus: DB không ép bằng UNIQUE INDEX (không diễn tả được "tối đa N" trong SQLite);
-- chặn ở tầng ứng dụng khi ghi to_status='focus' — đếm COUNT(*) WHERE status='focus' AND topic_id=?,
-- từ chối nếu >= topics.settings_json.maxFocusNiches (mặc định 1, đổi 2 khi cần).

CREATE TABLE painpoints (
  painpoint_id TEXT PRIMARY KEY,
  topic_id TEXT NOT NULL, niche_id TEXT NOT NULL REFERENCES niches(niche_id),
  underlying_question TEXT NOT NULL,   -- câu hỏi ngầm = đề bài video
  situation TEXT, barrier TEXT, desired_outcome TEXT,
  quotes_json TEXT NOT NULL,           -- câu nguyên văn của viewer
  evidence_comment_ids_json TEXT NOT NULL,
  n_comments INTEGER NOT NULL, n_videos INTEGER NOT NULL, n_channels INTEGER NOT NULL,
  strength TEXT NOT NULL CHECK(strength IN ('strong','weak')),
  stage TEXT NOT NULL CHECK(stage IN ('preview','deep')),
  status TEXT NOT NULL DEFAULT 'proposed' CHECK(status IN ('proposed','confirmed','rejected')),
  created_by TEXT NOT NULL, created_at TEXT NOT NULL, decided_at TEXT
);
CREATE INDEX idx_painpoints_niche ON painpoints(topic_id, niche_id, status);

11 · Tiêu chí chấp nhận

  1. Sau Setup lướt: 5–8 ngách proposed, mỗi ngách có đủ ai/hoàn cảnh/vấn đề, điểm cơ hội kèm lý do, ≥ 1 painpoint xem trước có câu nguyên văn.
  2. 100% keyword active có niche_id do người xác nhận hoặc được đánh dấu chưa gán.
  3. DB từ chối ngách focus thứ hai trong cùng topic.
  4. Weekly: ≥ 75% search call thuộc keyword của (các) ngách focus, chia đều khi có 2 ngách (đo từ loop_ticks.keywords_searched_json).
  5. Daily D6: 0 search call; keyword mới đều có origin daily_title và bằng chứng ≥ 2 kênh.
  6. Mọi painpoint confirmed: ≥ 10 comment, ≥ 3 video, ≥ 2 kênh, ≥ 3 câu nguyên văn, trỏ về comment_id thật, có dòng decisions actor=human.
  7. Agent/loop không bao giờ ghi niche focus hay painpoint confirmed; hitl_violations (mở rộng cho niche/painpoint) = 0.
  8. Toàn bộ test + typecheck xanh; bay-tra-gop (vi) vẫn chạy chế độ dự phòng.
